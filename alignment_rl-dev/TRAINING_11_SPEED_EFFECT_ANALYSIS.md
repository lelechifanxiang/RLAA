### 1.3 速度瓶颈分析

#### 理论分析

假设每个环境步的开销分解：

```
单环境步耗时 = 1 / (3.41/12) = 0.293秒

开销分解（估算）:
1. MTF计算（光线追迹）:    ~0.15s  (51%)  <- 主要瓶颈
2. 网络推理（策略前向）:     ~0.02s  (7%)
3. 网络训练（gradient_steps=3）: ~0.10s  (34%)
4. 日志/回调/其他:           ~0.02s  (7%)
----------------------------------------------
总计:                        ~0.29s  (100%)
```

#### 瓶颈识别

**主要瓶颈（占比51%）**: MTF计算
- 每个环境步需要完整的光线追迹
- 当前配置: 64x64采样点 × 3频率 × 5视场 × 2方向
- GPU利用可能不充分（批处理不够大）

**次要瓶颈（占比34%）**: SAC训练开销
- gradient_steps=3：每环境步做3次梯度更新
- 这是SAC特性，但代价高昂

## 四、改进建议

### 4.1 提升训练速度（优先级：极高）

**当前瓶颈**: MTF计算占51%耗时

#### 方案1: 降低MTF采样精度 ⭐⭐⭐⭐⭐
```python
# config.py
mtf_grid_size = 32  # 从64降到32
```
- **预期提速**: 2-3x（采样点从64²=4096降到32²=1024）
- **代价**: MTF精度下降，但对RL训练影响小
- **建议**: 立即实施

#### 方案2: 减少gradient_steps ⭐⭐⭐⭐
```python
# train.py
gradient_steps = 1  # 从3降到1
```
- **预期提速**: 1.5x（训练开销占34%）
- **代价**: 可能需要更多环境步
- **建议**: 与方案1结合

#### 方案3: 降低评估/日志频率 ⭐⭐
```python
eval_freq = 20000  # 从10000增加
n_eval_episodes = 20  # 从50减少
```
- **预期提速**: 1.1x（边际收益小）
- **代价**: 监控粒度降低
- **建议**: 可选

#### 方案4: 使用近似MTF（长期） ⭐⭐⭐⭐⭐
```python
# 训练神经网络拟合MTF计算
# MTF_approx = NN(state, tolerance) 
```
- **预期提速**: 10-50x
- **代价**: 需要预训练，sim-to-real gap
- **建议**: 未来研究方向

**综合方案（推荐）**:
