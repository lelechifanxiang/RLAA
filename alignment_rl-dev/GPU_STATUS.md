### 1. 光线追迹 (Ray Tracing)
- 位置: `optics_core/tracing/_core.py`
- 操作: 逐面追迹，计算光线-表面交点和折射/反射
- 设备: **GPU** (trace_pupil_to_image在GPU上)

### 2. Huygens积分 (PSF计算)
- 位置: `optics_core/huygens_psf.py` 第674-696行
- 操作: 计算复振幅叠加
- 设备: **GPU**
- 优化: 使用ray_chunk_size=4096分块计算，避免OOM

### 3. FFT (MTF计算)
- 位置: `optics_core/huygens_mtf.py`
- 操作: 2D FFT计算MTF
- 设备: **GPU** (torch.fft在GPU上)

## 瓶颈分析

### 计算复杂度
对于32条光线配置：
- 光线数: 32² = 1,024条
- 视场数: 1个
- 波长数: 3个
- 表面数: 8个
- **总计算量**: 1,024 × 3 × 8 = 24,576次光线-表面交互

### 为什么不能更快？
1. **光线追迹是顺序操作**：需要逐面计算，无法完全并行
2. **Huygens积分计算量大**：每个像素需要对所有光线积分
3. **分块处理开销**：为避免OOM使用分块，增加了循环开销
4. **数据传输**：GPU-CPU之间有少量数据传输

## 结论

✓ **GPU已成功启用并正常工作**
✓ **当前速度(~2步/秒)是GPU加速后的真实性能**
✓ **显存充足(16GB)，未达到瓶颈**
✓ **瓶颈在于计算复杂度本身，而非硬件利用率**

### 进一步优化方向
1. **使用更少光线**: 降低到16条(256条光线)可能2x加速，但精度下降
2. **减少视场数**: 当前只用1个中心视场，已经是最小配置
3. **减少MTF频点**: 当前3个频点，可减少到1-2个
4. **代码级优化**: 需要在optics_core内核层面优化，工作量大

### 建议
- 保持当前32条光线配置（速度与精度平衡）
- 使用4-8个并行环境训练
- 预期训练时间: 16-32小时（1M步）
- 如需加速，可牺牲精度降到16条光线
