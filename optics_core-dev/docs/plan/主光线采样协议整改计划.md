# 主光线采样协议整改计划

## 背景

当前部分采样器会按“缺少 `(0, 0)` 时再补主光线”的方式工作。这会导致偶数/奇数网格行为不一致，也会让 PSF 这类对采样数量和权重敏感的分析悄悄多出一条光线。

本项目强调批量并行追迹，因此主光线不应单独追迹。更合适的方式是把主光线和普通采样光线放在同一个 batch 中，但明确约定它是 reference ray，不参与默认积分和统计。

## 整改宗旨

1. 保持主光线与普通光线同批追迹，避免额外 trace。
2. 固定自动采样器的主光线位置，减少分析代码判断。
3. 不破坏 `ExplicitPupilSampler` 的显式采样语义。
4. 让 PSF、spot、wavefront 等分析能用同一套规则排除 reference chief ray。

## 采样协议

### 自动采样器

适用于：

1. `SquarePupilSampler`
2. `HexapolarPupilSampler`
3. `RandomPupilSampler`
4. 后续新增的非显式采样器

统一规则：

1. 先生成原始采样光线。
2. 在末尾追加一条 reference chief ray，坐标固定为 `(0, 0)`。
3. `chief_ray_index = ray_count - 1`。
4. 追加主光线的 `weight = 0.0`。
5. 原始采样点即使已经包含 `(0, 0)`，也不作为 reference chief ray；末尾追加的点才是唯一 reference chief ray。

### 显式采样器

`ExplicitPupilSampler` 默认不追加主光线。

原因：

1. 显式采样常用于 Zemax 单光线/多光线对标，输入几根就应该追迹几根。
2. layout、CB trace 等测试依赖固定采样数量。
3. 如果未来需要显式采样也携带主光线，应增加显式参数，而不是默认追加。

## 统计和积分规则

不建议在每个分析中扫描 `weights > 0` 来判断参与积分的光线。这样会增加分散判断，也容易漏。

自动采样器已经保证 reference chief ray 位于最后一根，因此分析代码可直接使用切片：

```python
sample_ray_slice = slice(0, chief_ray_index)
chief_ray_index = sample.chief_ray_index
```

含义：

1. `sample_ray_slice`：参与积分/统计的普通采样光线。
2. `chief_ray_index`：只用于参考像点、OPD reference、Refer To Chief Ray。

对于没有 `chief_ray_index` 的显式采样结果，分析代码不做默认排除，全部光线按显式输入处理。

## 需要修改的内容

### 1. 修改 `SamplingResult`

建议增加一个只读语义字段：

```python
sample_ray_count: int | None = None
```

自动采样器中：

```python
sample_ray_count = 原始采样光线数量
chief_ray_index = sample_ray_count
```

分析代码可用：

```python
sample_ray_slice = slice(0, sample.sample_ray_count)
```

这样比每次写 `slice(0, chief_ray_index)` 更直观，也避免未来显式采样没有 chief ray 时产生歧义。

### 2. 删除 `_append_chief_ray_if_missing()`

不再根据坐标内容推断主光线。

同时删除 `_chief_ray_index_from_coordinates()`，不再根据坐标反推主光线。

### 3. 新增统一 helper

在 `sampling.py` 中新增内部函数：

```python
def _append_reference_chief_ray(
    coordinates: torch.Tensor,
    weights: torch.Tensor,
) -> SamplingResult:
    ...
```

该函数负责：

1. 追加 `(0, 0)`
2. 追加 `weight=0`
3. 设置 `chief_ray_index`
4. 设置 `sample_ray_count`

### 4. 修改自动采样器

1. `SquarePupilSampler`：固定追加 reference chief ray，不再判断是否已有 `(0,0)`。
2. `HexapolarPupilSampler`：保留原中心点作为普通采样点，再末尾追加 reference chief ray。
3. `RandomPupilSampler`：末尾追加 reference chief ray。

### 5. 修改 `build_input_rays_from_sample`

继续把以下字段写入 metadata：

1. `chief_ray_index`
2. `pupil_coordinates`
3. `sample_ray_count`

后续分析模块从 metadata 读取，避免重新采样或重新推断。

### 6. 修改分析模块

优先修改：

1. `spot_diagram.py`
2. `huygens_psf.py`
3. 后续 wavefront/OPD 分析

规则：

1. chief ray 用于参考。
2. 统计/积分使用 `slice(0, sample_ray_count)`。
3. 不用 `weights > 0` 扫描排除主光线。

## 测试计划

### contract 测试

新增或修改采样器契约测试：

1. 自动采样器最后一根一定是 `(0, 0)`。
2. 自动采样器 `chief_ray_index == ray_count - 1`。
3. 自动采样器最后一根 `weight == 0`。
4. 自动采样器 `sample_ray_count == ray_count - 1`。
5. `ExplicitPupilSampler` 不追加主光线。

### 回归测试

运行并修复：

1. `tests/contract`
2. spot diagram 回归
3. Huygens PSF 回归
4. benchmark 中使用随机采样的测试

## 注意事项

1. 这次整改只解决主光线协议，不同时重写 Huygens 积分公式。
2. PSF 与 Zemax 的剩余差异仍需继续从 OPD reference、传播核、振幅因子排查。
3. 所有显式采样测试的 ray count 不应变化。
4. 如果某个分析确实希望把原始中心采样点纳入积分，应保留它的正权重；只有末尾 reference chief ray 被排除。
