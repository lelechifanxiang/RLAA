# 真实材料功能开发计划

## 1. 目标

当前阶段只做三件事：

1. 从 `optics_core/material/GLASS.xlsx` 读取真实玻璃数据
2. 把 Excel 中的玻璃按名称加载到 `MaterialLibrary`
3. 在现有光线追迹链路中直接使用 `RealMaterial`

这次开发不追求做成完整的玻璃数据库系统，核心目标仍然是：代码少、接口少、能尽快用于实际追迹和回归测试。

---

## 2. 设计原则

1. 不新增材料相关的类
   真实材料相关逻辑尽量并入 `MaterialLibrary`，减少概念数量。

2. 真实材料只支持通过 Excel 读取  
   不设计单独的“用户手工注册真实材料”流程。

3. 当前支持 `Sellmeier1`，并为 Cooke 用例中的 `H-ZK9A` 保留最小 `Schott` 支持  
   文档和实现都不展开介绍完整公式体系。

4. 尽量不动 tracing 主链  
   现有追迹层已经只依赖 `medium.refractive_index(wavelength_um)`，真实材料功能应主要落在材料层。

5. 内部实现允许保留最小私有数据结构  
   例如 `MaterialLibrary` 内部可临时保存解析后的原始行数据，但不额外暴露新的 public 类。

## 3. 推荐实现

### 3.1 改动位置

主改动放在 [materials.py](/c:/Users/Huwei/Project/auto_od_web/worker/auto_od/GYOptics/optics_core/optics_core/materials.py:1)。

当前文件里已经有：

1. `Material`
2. `RealMaterial`
3. `MaterialLibrary`
4. `Sellmeier1` 和 Cooke 用例所需 `Schott` 对应的折射率计算

因此这次开发应以补充 `MaterialLibrary` 的成员函数为主，而不是再加一套目录层。

### 3.2 推荐接口

给 `MaterialLibrary` 增加两类能力：

1. 读取 Excel
2. 按名称解析真实玻璃

接口尽量保持简单，建议控制在下面这个范围：

```python
class MaterialLibrary:
    def load_real_materials_from_excel(self, path: str | Path) -> None: ...
    def load_builtin_real_materials(self) -> None: ...
```

说明：

1. `load_real_materials_from_excel(...)`
   读取 Excel，解析出所有支持的真实玻璃，并直接注册到当前 `MaterialLibrary`

2. `load_builtin_real_materials()`
   默认读取仓库自带的 `optics_core/material/GLASS.xlsx`

加载完成后，用户直接通过已有机制使用即可：

```python
library = oc.MaterialLibrary()
library.load_builtin_real_materials()
material = library.resolve("H-K9L")
```

或者：

```python
architecture.surfaces.add_sphere(
    radius=50.0,
    thickness=5.0,
    medium="H-K9L",
)
```

前提是该名称已经被加载进 `MaterialLibrary`。

### 3.3 Excel 解析范围

当前阶段只解析真实会用到的字段：

1. 玻璃名称
2. 公式类型
3. `Nd`
4. `Vd`
5. `K1/L1/K2/L2/K3/L3`
6. `density`
7. `cost`

其中：

1. 只有 `Sellmeier1` 和 `Schott` 条目参与加载
2. 其他条目直接跳过，或显式报未实现异常，二选一即可
3. 新增`density` 和 `cost` 

Excel 表结构非常规整，不要为了“通用”引入额外复杂适配。

## 4. 开发步骤

### 阶段 1：补齐 `MaterialLibrary` 的 Excel 读取能力

目标：

1. 能读取 `optics_core/material/GLASS.xlsx`
2. 能找到一个已知玻璃，例如 `H-K9L`
3. 能把该条目转换成 `RealMaterial`

实现建议：

1. 在 `MaterialLibrary` 内部新增 Excel 读取函数
2. 逐行解析支持的玻璃数据
3. 为每条有效记录构造 `RealMaterial`
4. 直接调用现有 `register(...)` 写入材料库

### 阶段 2：让系统构建可以直接使用真实玻璃名

目标：

1. 加载 Excel 后，`MaterialLibrary.resolve("H-K9L")` 能返回真实材料
2. 系统构建时可以像普通材料名一样引用真实玻璃

实现建议：

1. 不改 `resolve(...)` 的外部语义
2. 只保证真实材料在加载后已经注册进库中
3. tracing 层不单独加分支

### 阶段 3：补最小回归测试

目标：

1. 验证 Excel 读取正确
2. 验证折射率计算正确
3. 验证真实材料能进入实际追迹链路

---

## 5. 测试计划

当前阶段建议只保留三类测试：

1. `MaterialLibrary` 读取 `GLASS.xlsx` 后，能解析出已知玻璃名
2. 已知玻璃在若干波长下的折射率与 Zemax 直接参考值一致
3. 用真实玻璃构建一个最小球面系统，追迹结果与 Zemax 对齐

测试重点放在“折射率是否正确”和“是否真的进入追迹链路”，不要一开始扩展太多 fixture 和目录结构。

---

## 6. 本阶段不做的事

1. 不做新的 public catalog 类型
2. 不做手工录入真实材料接口
3. 不做 `nd/vd -> 最近真实玻璃` 匹配
4. 不做多目录选材
5. 不做 `Sellmeier1` 和 `Schott` 之外的其他公式类型
6. 不做成本、密度筛选

这部分边界尽量在文档里一次说清，后面开发时就不再重复展开。
