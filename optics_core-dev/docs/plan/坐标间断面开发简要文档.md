# 坐标间断面开发简要文档

## 1. 目标

为 `optics_core` 后续开发 `CoordinateBreak` 提供一个足够清晰的起点，重点回答三个问题：

1. Zemax 的坐标间断面到底能做什么。
2. 这么多坐标变换相关功能里，当前阶段最值得先对齐哪一种。
3. 对 `optics_core` 来说，第一版应该支持哪些能力，哪些先不做。

---

## 2. 当前项目起点

当前仓库里已经有 `CoordinateBreak` 公开类型，但追迹内核还未实现真实坐标变换：

- `optics_core/surfaces.py`：已定义 `CoordinateBreak`
- `optics_core/tracing/_dispatch.py`：遇到 `CoordinateBreak` 直接 `NotImplementedError`

这意味着当前阶段最重要的不是继续包装接口，而是先把 Zemax 的最小语义定准。

---

## 3. Zemax 坐标间断面的功能梳理

### 3.1 Coordinate Break 的基本语义

Zemax 的 Coordinate Break 本质上是一个“改坐标系”的顺序面：

- 它本身不是有光焦度的真实光学面
- 它不会定义介质边界
- 它的玻璃始终继承前一面
- 它的作用是：从“前一面的局部坐标系”出发，生成一个新的局部坐标系，供后续表面继续使用

Zemax 的 Coordinate Break 关键参数有 6 个：

1. `Decenter X`
2. `Decenter Y`
3. `Tilt About X`
4. `Tilt About Y`
5. `Tilt About Z`
6. `Order Flag`

此外，`Thickness` 也属于 Coordinate Break 的重要组成部分，但它不是第 6 个参数，而是标准的厚度列。它表示沿“新坐标系 z 轴”继续传播到下一面的距离。

---

### 3.2 两种坐标变换顺序

Zemax 的 Coordinate Break 有两种常见执行顺序，由 `Order Flag` 控制。

#### `Order Flag = 0`

先平移，再旋转：

1. `Decenter X`
2. `Decenter Y`
3. 绕当前局部 `X` 旋转
4. 绕新的局部 `Y` 旋转
5. 绕新的局部 `Z` 旋转
6. 最后应用 `Thickness`

这是 Zemax 中最直观的一种顺序，很多简单倾斜、偏心建模都可以这样理解。

#### `Order Flag != 0`

先旋转，再平移：

1. 绕当前局部 `Z` 旋转
2. 绕新的局部 `Y` 旋转
3. 绕新的局部 `X` 旋转
4. `Decenter X`
5. `Decenter Y`
6. 最后应用 `Thickness`

这个顺序最重要的用途，不是“更常用”，而是“更适合撤销前一个复合变换”。  
Zemax 官方文档明确说明：它非常适合用一个共点的第二个 Coordinate Break 去撤销前一个 Coordinate Break 的复合 tilt/decenter。

---

### 3.3 Coordinate Return

Coordinate Return 是 Zemax 在 Coordinate Break 上提供的“自动返回到某个旧坐标系”的能力。它只存在于 Coordinate Break 上。

可选模式有：

1. `None`
2. `Orientation Only`
3. `Orientation XY`
4. `Orientation XYZ`

含义分别是：

- `Orientation Only`：只对齐姿态，不对齐位置
- `Orientation XY`：对齐姿态，以及顶点的 `x/y`
- `Orientation XYZ`：对齐姿态，以及顶点的 `x/y/z`

其中最实用的是 `Orientation XYZ`。  
它会把返回所需的 `x/y` 放到 Coordinate Break 参数里，把 `z` 放到该面 `Thickness` 上，使“下一面”的位置和姿态与目标面一致。

---

### 3.4 Surface Tilt/Decenter

Zemax 还有一套 `Surface Tilt/Decenter` 入口。  
它不是另一套数学，而是另一种界面形式，本质上仍然是在做局部坐标变换。

它的优点：

- Lens Data Editor 里看起来更紧凑
- 不需要显式插入那么多 dummy Coordinate Break

它的缺点：

- 对初学者不如显式 Coordinate Break 直观
- 对程序库实现来说，不如“明确的 Coordinate Break 面”好落地
- Zemax 官方文档也提到，这种方式在一些场景下不如显式 Coordinate Break 灵活

对 `optics_core` 当前阶段来说，不建议先做这层抽象。

---

### 3.5 Zemax 中 Coordinate Break 的典型用途

结合官方帮助和知识库，Coordinate Break 常见用途包括：

1. 倾斜/偏心单个表面
2. 倾斜/偏心整个镜片或一组表面
3. 围绕某个顶点、镜片中心、任意空间点进行 pivot
4. 建模折叠光路、扫描镜、棱镜、离轴元件
5. 为公差分析和 Local-to-Global 建模提供基础
6. 通过 Pickup / Position / Chief Ray solve 自动维持几何关系

其中真正最常见、也最值得先支持的，不是“所有 solve”，而是：

`前置 Coordinate Break 改坐标系 -> 在局部坐标系下定义一组表面 -> 后置 Coordinate Break / Coordinate Return 返回原坐标系`

---

## 4. 推荐的最常用对齐方式

### 推荐结论

当前项目建议优先对齐这条用法：

**显式 Coordinate Break + Coordinate Return(Orientation XYZ) + 面组局部坐标建模**

即：

1. 在某个表面组前插入一个 Coordinate Break
2. 用它定义新的局部坐标系
3. 后续若干面在这个局部坐标系下继续顺序追迹
4. 在表面组后插入一个 Coordinate Break，并使用 `Coordinate Return = Orientation XYZ` 返回到前置参考面

---

### 为什么推荐它

因为这条链路同时满足四个目标：

1. **最贴近 Zemax 常见建模方式**  
   Zemax 官方教程里，倾斜/偏心元件、任意点 pivot、恢复系统坐标，基本都围绕这套方式展开。

2. **对用户最直观**  
   “先改坐标系，局部建模，再返回”比 Surface Tilt/Decenter 那套 before/after 规则更容易读懂。

3. **对程序实现最稳**  
   内核里只要把“当前局部坐标系”处理对，后面的真实球面、非球面、镜面都能复用同一套 tracing 主链。

4. **对后续扩展最友好**  
   公差、装配、折叠光路、离轴镜组、layout、全局坐标输出，都会自然依赖这套能力。

---

## 5. 对 optics_core 的第一版建议范围

### 5.1 第一版建议支持

#### A. 显式 Coordinate Break 面

保留现在的 `CoordinateBreak` surface 类型，不做额外封装。

#### B. 基本参数

第一版至少支持：

- `Decenter X`
- `Decenter Y`
- `Tilt About X`
- `Tilt About Y`
- `Tilt About Z`
- `Order Flag`
- `Thickness`

#### C. 两种 Order Flag 顺序

虽然推荐用法里最常见的是“前置 CB + 返回 CB”，但为了真实对齐 Zemax，内核最好一开始就支持：

- `Order = 0`
- `Order != 0`

因为这只是两种刚体变换组合顺序，成本不高，但能显著减少后续 zmx 对照时的歧义。

#### D. Coordinate Return 只先做 `Orientation XYZ`

第一版建议只支持：

- `None`
- `Orientation XYZ`

暂时不做：

- `Orientation Only`
- `Orientation XY`

理由很简单：  
`Orientation XYZ` 是最完整、最常用、最不容易出错的一种返回方式，足够覆盖“局部面组建模后回到主系统坐标”的核心场景。

---

### 5.2 第一版暂时不要做

当前阶段不建议一上来就实现下面这些功能：

1. `Surface Tilt/Decenter` 这套替代入口
2. `Chief Ray solve`
3. `Pickup / Position solve` 的完整 Zemax 求解器语义
4. `Local to Global` 工具级别封装
5. 公差自动插入 Coordinate Break
6. 任意多层嵌套 return 规则的 UI 级仿真

这些能力未来都可能要有，但第一版先把“真实坐标变换 + 顺序追迹 + zmx 对齐”做对更重要。

---

## 6. 推荐的数据结构和执行语义

### 6.1 不建议复用通用 `CoordinateFrame` 直接表达 Zemax Coordinate Break

原因是 Zemax 的 Coordinate Break 不是一个普通 pose：

- 它有 `Order Flag`
- 它有 `Coordinate Return`
- 它的 `Thickness` 语义特殊
- 它是顺序追迹链上的“改坐标系节点”，不是一个孤立的全局位姿

因此更合适的做法是：

- `CoordinateBreak` 保留为独立 surface 类型
- 显式保存：
  - `decenter_x`
  - `decenter_y`
  - `tilt_x_deg`
  - `tilt_y_deg`
  - `tilt_z_deg`
  - `order_flag`
  - `return_mode`
  - `return_to_surface`
- `gap.thickness` 继续承担 Zemax 中的 `Thickness`

---

### 6.2 推荐的内核实现思路

推荐在 tracing runtime 中维护“当前局部坐标系”的刚体变换：

1. 进入 Coordinate Break 时，更新当前 frame
2. 后续真实表面都在当前局部 frame 下求交、求法向、折反射
3. 当遇到 `Coordinate Return = Orientation XYZ` 时，把当前 frame 直接恢复到目标 surface 对应的 frame
4. 恢复后再继续应用该 Coordinate Break 的 `Thickness`

从数学实现角度，最适合统一成：

- `3x3 rotation + 3x1 translation`
- 或者直接 `4x4` 齐次刚体变换

这会比在 tracing 主循环里散落很多 `x/y/z/l/m/n` 特判更清楚。

---

## 7. 最小测试建议

建议第一轮只做 4 组回归，全部直接和 Zemax 对比：

### 测试 1：纯 X/Y decenter

目标：

- 验证 Coordinate Break 只改位置，不改姿态
- 验证后续球面交点位置与 Zemax 一致

### 测试 2：纯 X/Y/Z tilt

目标：

- 验证局部坐标轴旋转正确
- 验证后续球面交点和像面结果与 Zemax 一致

### 测试 3：复合 tilt + decenter + 两种 order

目标：

- 验证 `Order = 0` 和 `Order != 0` 确实给出不同结果
- 验证两种顺序都能对齐 Zemax

### 测试 4：前置 CB + 面组 + Coordinate Return XYZ

目标：

- 验证局部面组建模和“返回主坐标系”正确
- 验证返回后的后续面、像面位置不漂移

这 4 组一旦通过，第一版 Coordinate Break 的几何主链基本就站住了。

---

## 8. 最终建议

如果只给当前阶段一句开发建议，我会建议：

**先把 Coordinate Break 当成“顺序追迹里的局部刚体变换节点”，只做显式 CB + Order Flag + Coordinate Return XYZ，不要一开始就做 Surface Tilt/Decenter 和各种 solve。**

这样最省代码，也最容易把 Zemax 对齐做实。
