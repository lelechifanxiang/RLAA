# 同架构异构参数并行追迹支持分析

## 1. 需求边界

多个设计组成同一 batch 时，约束如下：

- 表面数量、表面类型和排列顺序一致；
- 波长数量、物理波长、权重和主波长一致，共用一套波长定义；
- 系统孔径类型一致，STOP 表面位置一致，孔径数值允许逐设计不同；
- 视场类型和视场数量一致，视场坐标允许逐设计不同；
- 各表面的几何参数和材料允许逐设计不同。

追迹张量保持规则的 dense 形状：

```text
[design, field, wavelength, ray]
```

上述约束避免了波长、视场和表面维度的 padding，也不需要 ragged tensor。

## 2. 参数差异对吞吐量的影响

### 2.1 结论

在固定拓扑和固定张量维度下，参数数值不同不会使追迹退化为逐设计串行。表面类型分发仍然只执行一次，各设计的曲率、厚度、孔径、视场和材料索引通过 tensor 广播或 gather 进入同一批计算。因此，异构 batch 的 GPU kernel 吞吐量预计接近相同规模的同构 batch，并行收益仍然存在。

本需求又明确共享波长、视场数量和 STOP 位置，因此不存在为不同维度补齐空槽的问题，比通用异构 batch 更适合 GPU dense 计算。

具体加速倍数仍应在 CUDA 环境实测，不能仅根据结构推断。

### 2.2 可能降低有效吞吐的因素

| 因素 | 对计算的影响 |
| --- | --- |
| 材料、曲率、厚度、孔径和视场值不同 | 运算形状和 kernel 数量不变，通常只有少量 gather、广播和显存访问差异。 |
| 各设计渐晕或追迹失败比例不同 | 当前不会压缩无效光线，后续表面仍按完整 tensor 计算；原始 rays/s 变化不大，但 valid rays/s 会下降。 |
| batch 过大 | 中间张量规模约为 `D×F×W×R`；显存不足时需要 design minibatch。Spot 和普通追迹目前没有自动 minibatch。 |
| 数据准备 | 材料表在 `prepare()` 中一次编译；几何参数仍由 `surface_value()` 从 Python 参数向量临时组装 tensor。大 batch 或频繁追迹时，CPU 和 CPU→GPU 开销可能明显。 |
| 评价阶段 | Wavefront、PSF/MTF 的 OPD、FFT 和图像网格计算可能比追迹更重，端到端吞吐不能只看追迹 kernel。 |

材料差异不会产生 Python 级逐设计分支。当前运行时使用 `[design, surface]` 材料索引查询共享的 `[material, wavelength]` 折射率表；本需求中波长完全共享，现有结构正好适用。

### 2.3 建议的 benchmark 口径

在相同 `D/S/F/W/R` 下比较同构与异构 batch，并同时报告：

1. 追迹 kernel 的 rays/s；
2. 包含准备和评价的 designs/s；
3. valid rays/s 和平均有效率；
4. 峰值显存和实际 design minibatch 大小。

## 3. 当前支持情况

| 需求 | 当前状态 | 说明 |
| --- | --- | --- |
| 共享波长 | 已支持 | `WavelengthSequence`、权重、primary index 和折射率表均为全 batch 共享。 |
| 逐设计材料 | 已支持 | `gap.medium` 可按设计、按表面变化，准备阶段编译为材料索引。 |
| 逐设计系统孔径值 | 已支持 | `SystemAperture.value` 可为 `[design]` tensor；系统孔径类型和 STOP 位置共享。 |
| 逐设计视场坐标 | 部分支持 | `build_pupil_rays()` 已支持 `[design, field, 2]`，标准 Spot/Wavefront/PSF 入口仍读取共享 `system.fields`。 |
| 逐设计半径、圆锥系数和厚度 | 已支持 | 热路径通过 `surface_value()` 读取；表面类型必须相同。 |
| 逐设计近轴面焦距 | 已支持 | `geometry.focal_length` 可逐设计变化。 |
| 逐设计表面半口径 | 已支持 | `semi_diameter` 可逐设计变化，solve 和 Surface Aperture 类型保持共享。 |
| 逐设计坐标间断参数 | 已支持 | x/y 偏心、rx/ry/rz 倾斜和 order 可变化，CB 的有无和位置必须共享。 |

## 4. 与新需求相比的实际缺口

### 4.1 孔径 batch 组装

底层一阶计算接受 `[design]` 的系统孔径值；`examples/batch_spot_multiple_zmx.py::repeat_system()` 已使用同一组 design index 同步循环选择参数向量和孔径值。CPU、10-design 的 Spot 结果与 Zemax 最大差异约为 `1.2e-9 μm`。

此外，`object_na` 虽在类型定义中存在，但一阶孔径解析尚未实现；它不属于当前 ENPD、F/#、FLOA 需求。

### 4.2 视场进入标准分析链路

低层 `build_pupil_rays()` 已经能够构造逐设计视场光线，当前五文件 Spot 辅助链路也在使用这一能力。但：

- `MultiOpticalSystem.fields` 仍是一套共享的 `FieldSequence`；
- Spot、Wavefront、PSF/MTF 的标准入口会把共享视场复制到所有设计；
- 分析结果中的视场标签和导出信息也来自共享 fields。

因此，逐设计视场目前只在专用辅助链路可用，还不是完整的系统级能力。需要在准备态保存 `field_angles[D,F,2]`，并让所有分析模块统一读取。

本需求要求 field 数量和 field type 一致，所以不需要 field mask 或 padding。视场权重、渐晕参数是否允许逐设计变化尚未纳入本需求，可继续保持共享。

### 4.3 材料和表面参数边界

- 所有材料必须能从共享材料库解析；逐设计材料选择已经支持。
- 同名材料的色散系数不能逐设计变化，如有需要应注册为不同材料。
- 非空偶次非球面系数尚未实现，也不支持其逐设计变化。
- `ParameterSchema` 可以声明任意属性路径，但批量热路径目前明确读取 radius、conic、focal length、thickness、medium、semi-diameter 和 CB 参数。
- `object_distance_mm`、`afocal_image_space`、表面数、表面类型、STOP/CB 位置必须共享。

## 5. Semi-Diameter solve、Surface Aperture 与并行的关系

Semi-Diameter 的 `fixed/auto` solve 本身不会降低 GPU 并行度，它只决定准备阶段是否自动回填表面尺寸。真正参与追迹裁剪的是独立的 Surface Aperture：

- `none` 不按 Semi-Diameter 裁剪；
- `floating` 按逐设计 Semi-Diameter 裁剪。

当前这两类属性都是同架构设计共享的 Python 字符串，每个表面只执行一次共享分支，因此不会造成逐设计分支发散。Semi-Diameter 数值仍是 `[design]` tensor。

如果将来需要逐设计改变 Surface Aperture 类型，可以编译为 `aperture_mask[D]`，并统一计算：

```text
valid = valid & (~aperture_mask | inside_aperture)
```

这样仍是一次 tensor 运算，不需要逐设计 Python 分支。只有硬孔径产生大量无效光线时，有效 rays/s 才会下降；这属于有效工作量变化，不是并行度下降。

当前需求不要求逐设计改变 solve 或 Surface Aperture 类型，继续作为共享拓扑属性即可。

## 6. 建议的开发顺序

1. 在系统准备态增加 `field_angles[D,F,2]`，让 Spot、Wavefront、PSF/MTF 和显式 pupil 光线共用。
2. 将 radius、conic、thickness、口径和 CB 参数预编译为 tensor，避免每次 trace 从 Python 参数向量重新组装。
3. 在 CUDA 环境按第 2.3 节同时比较同构和异构 batch 的 kernel 与端到端吞吐。

不需要开发逐设计波长、不同 field 数量或 ragged batch。完成前 2 项后，新需求中的孔径、视场和材料差异即可在追迹前一次准备完毕，热路径保持固定拓扑和纯 tensor 计算。
